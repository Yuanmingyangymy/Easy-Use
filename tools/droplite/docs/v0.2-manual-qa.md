# DropLite v0.2 Manual QA

This checklist is for the `feat/droplite-desktop-to-phone` development branch. It validates the bidirectional v0.2 preview flow while protecting the v0.1 phone-to-desktop baseline.

## Windows Desktop Setup

1. Connect the Windows computer and phone to the same non-guest Wi-Fi.
2. Set the current Windows Wi-Fi network to Private.
3. Allow DropLite through Windows Firewall for Private networks if prompted.
4. Start the development build:

```bash
cd tools/droplite
npm run tauri:dev
```

5. Confirm the desktop app shows a QR code, session timer, receive folder, and `Send to phone` panel.
6. Confirm the receive folder is readable and writable.

## Phone Scan

1. Scan the QR code with the phone browser.
2. Confirm the mobile page opens on the local network.
3. Confirm the mobile page shows two tabs:
   - `Send to desktop`
   - `Receive from desktop`
4. Confirm the page language follows the desktop language or the `lang` URL parameter.

## Phone -> Desktop Regression

Run these from the `Send to desktop` tab:

1. Send text and confirm it appears in `Recently received`.
2. Send a JPG or PNG photo and confirm:
   - it is saved in the current receive folder
   - the timestamp filename is readable
   - the desktop list shows the image item
   - no `.part` file remains
3. Use `Take photo` and confirm the same behavior.
4. Send a small MP4 and confirm the video saves completely and can play.
5. Send a PDF or ZIP and confirm it saves and appears in the desktop list.
6. Change the receive folder, send another file, and confirm it is saved in the new folder.
7. Reset the receive folder, send another file, and confirm it returns to the default `Downloads/DropLite` folder.

## Desktop -> Phone Regression

Run these from the desktop `Send to phone` panel and the phone `Receive from desktop` tab:

1. Add text on the desktop.
2. Confirm the phone receive tab shows the text card.
3. Copy the text on the phone and confirm the copied text is correct.
4. Choose a file on the desktop.
5. Confirm the phone shows one file card with name, size, type, and sent time.
6. Drag one file into the desktop app.
7. Confirm the phone shows only one new item for that single drop.
8. Drag multiple different files at once.
9. Confirm each file appears once.
10. Re-drag the same file in a separate action and confirm a new item is created intentionally.

## System Browser Download Test

Use Android Chrome, iOS Safari, or the phone's default system browser:

1. Add a PDF from the desktop.
2. Tap `Download` on the phone.
3. Confirm the browser starts a download or opens the file.
4. Add a photo and repeat.
5. Add a video and repeat.
6. Confirm `Copy download link` copies a token-protected link.
7. Confirm copying the link does not mark the item as downloaded.

## WeChat In-App Browser Limit

WeChat's in-app browser may block direct file downloads. This is a browser limitation, not a DropLite cloud or permission feature.

1. Open the QR page in WeChat.
2. Add a downloadable item from the desktop.
3. Confirm the phone page shows the WeChat-specific hint:
   - open the top-right menu
   - choose to open the page in the system browser
   - download the file there
4. Tap `Download` and confirm the page shows fallback guidance instead of claiming success.
5. Tap `Copy download link` and confirm the link is copied.
6. Confirm copying a download link does not mark the item as downloaded.

## Refresh Session

1. Open the mobile page and add a text item from the desktop.
2. Confirm the old phone page can list the item.
3. Click `Refresh session` on the desktop.
4. Confirm the old phone page shows the expired-session state or cannot list/download/ack outbox items.
5. Scan the new QR code.
6. Confirm the new session starts with an empty outbox.

## Token Expiration

1. Let the session expire or shorten the session during local testing.
2. Confirm phone-to-desktop upload is rejected.
3. Confirm outbox list is rejected.
4. Confirm file download is rejected.
5. Confirm ack is rejected.
6. Confirm the UI shows a friendly expired-session message.

## Known Limitations

- v0.2 is still a development branch, not a published stable release.
- Desktop-to-phone uses local-network HTTP and is not encrypted.
- It is not recommended on public or untrusted Wi-Fi.
- Phone browser download behavior differs across Android Chrome, iOS Safari, and embedded browsers.
- WeChat's in-app browser may block downloads; use the system browser fallback.
- Downloaded files are handled by the phone browser and operating system. DropLite does not guarantee automatic saving to the gallery.
- Only the current temporary session can access outbox items.
- There is no cloud relay, account system, database, WebRTC, chat, or permanent transfer history.
